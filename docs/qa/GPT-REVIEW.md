## Ինտրո՝ պահպանված պահանջով

Մոմի անիմացիայի գույները, ձևը, առաջին այցի 3.6 վայրկյանանոց ցուցադրումը և 2 վայրկյանանոց ավարտը պահպանվել են։ Այն այլևս չի սպասում նկարների, font-երի կամ `window.load`-ի ավարտին։ Render-ը սկսվում է hydration-ից հետո, որպեսզի առանց JavaScript-ի SSR բովանդակությունը չծածկվի։

Այսինքն՝ տեսողական ինտրոն մնում է, բայց այն այլևս ցանցի պատրաստության ցուցիչ չէ։ Դանդաղ կապով ներքևի նկարները կարող են շարունակել բեռնվել ինտրոյից հետո։ Առաջին hydration-ի պահին հնարավոր կարճ բացված էջ → ինտրո անցումը պետք է դիտել իրական դանդաղ սարքով։

## Գաղտնիություն, cache և որոնման ծախսեր

- Service worker-ի տարբերակը `v6` է՝ հին page cache-երը հեռացնելու համար։ HTML/`.data` պատասխանն offline cache-ում պահվում է միայն սերվերի `X-Offline-Public: 1` թույլտվությամբ և երբ `private/no-store` չէ։
- Worker-ը այդ թույլտվությունը տալիս է հանրային JSON-ին կամ իր արդեն cacheable անանուն պատասխաններին։ DEV միջավայրի ավտոմատ տեղային հաշիվը հանրային չի հայտարարում։
- Հաշվի փոփոխության և գրող գործողությունների ժամանակ page cache-ը մաքրվում է։ Չի նախապահվում հավանական signed-in գլխավոր էջը։ Գրելուց առաջ սկսված պատասխանը չի պահվում ավելի ուշ։
- Անձնական էջի offline հասանելիությունը չի խոստացվում։ Հանրային հաստատված էջերը, assets-ը և նկարները շարունակում են ունենալ cache։ Static cache-ն այժմ ունի 160 ֆայլի սահման, page/media սահմանները՝ 250/400։
- D1 հիշողության cache-ը պահում է ավարտված արժեքներ՝ չկիսելով pending I/O Promise-ները հարցումների միջև։
- Որոնման ինդեքսի բացակայող/հին `v`-ն նախ վերահղվում է ընթացիկ տարբերակին. ամբողջ ինդեքսը չի կառուցվում հին հասցեի համար։ Նույն տարբերակի արդյունքը հիշվում է սերվերի հիշողության մեջ։ Browser-ը redirect ստացած ինդեքսը չի գրում հին տարբերակի ձեռքով cache-ի տակ։
- Բաց tab վերադառնալիս կատարվում է էժան content-version ստուգում՝ առավելագույնը մեկ անգամ 5 րոպեում։ Փոփոխության դեպքում navigation cache-ը մաքրվում է և root-ը թարմացվում։ Background polling չկա։
- Հուշումները կապվել են ինդեքսի տարբերակի և բաժնի հետ։ Գրելիս որոնման հարցումներ չեն գնում. առաջին օգտագործման ժամանակ կարող է ներբեռնվել վերնագրային ինդեքսը, իսկ տեքստային fallback-ը մնում է սերվերում։

**Չլուծված մաս.** Սառը search index-ը դեռ կառուցվում է D1-ից՝ ամբողջ գրադարանի համար։ Նախապես պատրաստված R2 ինդեքս այս ճյուղը չի ներմուծում։ Մշտապես foreground մնացող tab-ի ինդեքսը ինքնուրույն պարբերաբար չի ստուգվում. ստուգումը visibility return-ի պահին է։ Worker-ի ներսում cache hit-ը դեռ Worker invocation է, զրո request/CPU չենք խոստանում։

## Մեդիայի տարբերակավորում և անվտանգ անցում

Telegram adapter-ը փոխանցում է `sourceFileId` (`document-…`/`photo-…`)՝ միայն ֆայլի ID, ոչ գաղտնի access hash։ Նոր ֆայլերի բանալիները կախված են այդ ինքնությունից, ոչ caption-ից։ Տեքստի խմբագրումը փոխում է նյութի hash-ը, բայց նույն ֆայլի key-ը մնում է նույնը։ Փոխարինված Telegram ֆայլը ստանում է այլ key։

Համատեղելիության համար հաշվարկվում է նաև հին ձևաչափի hash-ը։ Եթե հին նյութը և դրա ֆայլերը անփոփոխ են, այն բաց է թողնվում՝ առանց զանգվածային վերավերբեռնման։ Հին նյութի առաջին իրական խմբագրումը կարող է մեկ անգամ ստեղծել նոր file-ID տարբերակը։ Հետագա տեքստային խմբագրումները վերօգտագործում են այն։ Առանց sourceFileId-ի adapters/fixtures-ը պահում են հին վարքը։

Ստուգումները հաստատում են՝

1. Caption-ի փոփոխությունից file key-ը չի փոխվում։
2. Իրական file ID-ի փոփոխությունից key-ը փոխվում է։
3. Անփոփոխ հին տվյալը `isCurrent()` է՝ հին key-ով։
4. Նոր key-ն առկա լինելու դեպքում stage-ը չի պահանջում նոր upload։

**Չեն ջնջվել հին R2 օբյեկտները։** Չկան bucket-ի ամբողջական inventory, պահպանման ժամկետի համաձայնեցված սահման և հրապարակված հղումների ստուգում։ Դրանց կույր ջնջումը կարող է կոտրել հին հղումները։ Հին օբյեկտների զբաղեցրած տարածքը այս փոփոխությունից ինքնուրույն չի ազատվի։ Telegram-ից ջնջված նյութի արդեն հայտնի ուղիղ R2 հղման հասանելիության հարցը նույնպես մնում է առանձին lifecycle/purge աշխատանք։

## Մյուս ուղղումները

- Sync debounce-ը սահմանափակված է՝ առաջին update-ից առավելագույնը 30 րոպե, սովորաբար վերջինից 15 րոպե։
- Dispatch-ի անհաջողությունների retry-ն սահմանափակված է՝ 1/2/4/8/16 րոպե։ Հետո կանգնում է և գրում սխալ. գիշերային fallback-ը մնում է։ Token-ի 401/403-ը դեռ առանձին դասակարգված չէ։
- OG workflow-ի կրկնվող push trigger-ը հանված է։ Ավտոմատ գործարկումը միայն հաջող Deploy/Cloud sync-ից հետո է, deployment-ի դեպքում միայն համապատասխան միջավայրի համար։
- Հիշեցման read/snooze/cancel-ի ձախողումները տեսանելի հայերեն հաղորդագրություն են տալիս։ Չհաջողված գործողությունից հիշեցումն այլևս տեղային ցուցակից չի հեռացվում որպես հաջողություն։
- Footer-ի հղումները ավելի ընթեռնելի են և ունեն ավելի մեծ սեղմման տարածք։ Մենյուի keyboard focus loop-ը ներառում է settings-ի input/select դաշտերը։
- Թեստային TypeScript project-ը ունի իր D1/Cloudflare տիպերը և DOM lib-ը՝ առանց production environment-ի փոփոխականները Node test fixtures-ին պարտադրելու։ `lint`-ը անցնում է։
- Ավելացված է QA workflow՝ review ճյուղի և main/staging PR-ների համար. այն կատարում է lint/typecheck/test և deploy չի անում։
- Հին auto-submit hook-ը փոխարինված է `useSearchSubmit`-ով, հեռացված են այլևս չօգտագործվող video-frame extraction-ը և section header-ի մեռած divider կոդը։

## Չփոխված որոշումներ և մնացած ռիսկեր

- Production/staging-ի ամբողջ տվյալների կրկնօրինակումը չի փոխվել. staging-ի տվյալների կրճատումը կարող է խանգարել գոյություն ունեցող փորձարկումներին և պահանջում է տվյալների հստակ սահմանում։
- Ամենօրյա GitHub sync fallback-ը պահպանվել է. սա դեռ կարող է կրկնվել Worker cron-ի հետ։ Առանց վերջին հաջող աշխատանքի վստահելի ընդհանուր վիճակի այն հանելն ավելի վատ վերականգնում կտար։
- Presence endpoint-ի abuse/rate-limit քաղաքականությունը չի փոխվել։ Cloudflare WAF-ի և իրական քվոտաների ստուգում դեռ պետք է։
- Գլխավոր էջի մեծ նկարն ու դասավորությունը պահպանվել են։ Լողացող մենյուի տեսողական տեղադրությունը վերաձևված չէ։
- Telegram/Google account chooser-ը և OS share sheet-ը արտաքին UI են. դրանց վերջնական վարքը պետք է ստուգել իրական սարքերով։
- Preview-ի սև կամ բացակայող Telegram thumbnail-ը դեռ պահանջում է մեկանգամյա server-side poster generation-ի առանձին լուծում։ Բրաուզերի թանկ ավտոմատ վիդեոներբեռնումը հանված է։
- Cloudflare-ի իրական CPU, D1 rows, R2 storage/operations, CDN hit rate և GitHub րոպեներ չեն չափվել։ «Միշտ անվճար» կամ տոկոսային խնայողության երաշխիք չկա։

## Claude-ի վերարտադրումը և review հերթականությունը

```bash
git fetch origin
git switch fix/gpt-qa-review
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
```

Browser fixture-ը նախատեսված է **դատարկ տեղային D1** բազայի համար։ Այն հրաժարվում է աշխատել, երբ կան նյութեր։

```bash
pnpm db:migrate:local
python3 scripts/qa-ui-fixture.py
pnpm dev --host 127.0.0.1 --port 5174
# Առանձին terminal. Chromium-ի ուղին փոխել, եթե անհրաժեշտ է։
CHROMIUM_PATH=/usr/bin/chromium node scripts/qa-ui-smoke.mjs
python3 scripts/qa-ui-fixture.py --remove
```

Հատուկ ուշադրություն դարձնել՝

1. `public/sw.js` + `workers/app.ts` հանրային cache-ի թույլտվությանը, logout/write մրցակցող հարցումներին և signed-in offline սահմանափակմանը։
2. `cloud-sync.ts` + `wrangler-cloud-target.ts` հին hash/key-ից նոր file-ID key անցմանը։ Remote dry-run և փոքր staging նյութի իրական edit/replace փորձը դեռ պետք է անել հրապարակումից առաջ։
3. Որոնման բոլոր մուտքերին՝ ընդհանուր էջ, բաժին, URL, pagination, մեկ նիշանոց սաղմոս, filter-only, saved scope։
4. Իրական iPhone/Android Telegram՝ share cancel, մուտքի վերադարձ, դանդաղ ցանցով շապիկ և հիշեցման ձախողում։
5. Workflow-ների trigger-ներին և իրական quota հաշվարկին։

Հետ շրջելու համար branch-ի փոփոխությունները կարելի է revert անել։ Արտադրական migration կամ remote տվյալների ջնջում չկա։ Հետագայում հրապարակելու դեպքում SW cache տարբերակի հետշրջումն էլ պետք է դիտարկել, որպեսզի սարքերում մնացած service worker-ը ժամանակին թարմացվի։
