## Վերարտադրված հիմնական խնդիրներ

### 1. Պահած նյութի կեղծ հաջողություն — P2

`app/hooks/use-saved-materials.ts:37–48`-ը գրանցում է տեղական override մինչև սերվերի պատասխանը և չի մշակում մերժումը։ Իրական hook-ը React Router-ի տեղական action-ով ստացավ `{saved:false,error:'material-unavailable'}`, HTTP 404։ Ավարտից հետո `savedIds.has(id)`-ը մնաց `true`։ Սա սերվերի action-ի իրական հնարավոր պատասխաններից է (`app/routes/saved.tsx`)։

Ուղղում՝ պահպանվող/պահված/սխալ վիճակներ, ձախողման ժամանակ override-ի հետարկում և կրկնելու հնարավորություն։ Հեռացված նյութի համար՝ բացահայտ հաղորդագրություն։

### 2. Հարցումը ասում է «պահված է»՝ POST 503-ի դեպքում — P2

`app/components/telegram-content.tsx:245–252`-ում պատասխանը նշվում է մինչև POST-ը։ Կոդը չի ստուգում response.ok-ը։ Իրական բաղադրիչի տեղական փորձը 503-ից հետո ցույց տվեց «Ձեր պատասխանը պահված է», իսկ ընտրությունները այլևս կոճակներ չէին։ Օգտատերը չի կարող նույն տեղում նորից ուղարկել պատասխանը։

Ուղղում՝ սերվերի հաստատումից հետո վերջնականացնել պատասխանը, կամ սխալի դեպքում վերադարձնել ընտրության հնարավորությունը և առաջարկել retry։

### 3. Հիշեցման բեռնման սխալը դառնում է «հիշեցում չկա» և այլևս չի կրկնվում — P2

`app/components/reminder-button.tsx:136–143`-ի load-ը HTTP 503-ը դարձնում է `{reminder:null}` և դնում `loaded=true`։ Տեղական փորձով սխալի հաղորդագրություն չեղավ. բացվեց նոր հիշեցման ձևը։ Պատուհանը փակելուց, սերվերի պատասխանը հաջող դարձնելուց և նորից բացելուց հետո **0 նոր GET** եղավ. կեղծ դատարկ վիճակը մնաց։ HTTP 200 + վնասված JSON-ը առաջացրեց չմշակված pageerror։

Ուղղում՝ «չհաջողվեց բեռնել»-ը չշփոթել բացակայության հետ, loaded-ը հաստատել միայն վավեր պատասխանից հետո, JSON սխալը մշակել, ավելացնել retry։ Բեռնման սխալի դեպքում չառաջարկել կուրորեն վերագրել հնարավոր գոյություն ունեցող հիշեցումը։

### 4. Կիսման fallback-ը հայտնում է «Պատճենվեց», երբ ոչինչ չի պատճենվել — P2

`app/components/share-button.tsx:19–34,62–65`։ Իրական shareLink-ին տրվեց միջավայր, որտեղ clipboard.writeText-ը մերժվում է և document.execCommand('copy')-ը վերադարձնում է false։ Արդյունքը դեռ `copied` էր։

Ուղղում՝ copyText-ը թող վերադարձնի հաջողության boolean կամ սխալ, UI-ն հաջողություն ցույց տա միայն հաստատված պատճենման դեպքում։ Ձախողման դեպքում՝ ընտրելի հղում և հասկանալի հուշում։ Գործող կայքի հաջողության ճանապարհով StoryEditor-ը բացվել է և հղումը տվել է `https://apostolic.am/pray/69`։ Կիսումը փորձարկվել է API-ի տեղական փոխարինմամբ՝ առանց որևէ մեկին հաղորդագրություն ուղարկելու։

### 5. Ընդհանուր բացվող պատուհանի focus-ը չի կառավարվում — P2

`app/components/bottom-sheet.tsx`-ը փակում է Escape-ով և արգելափակում էջի սահքը, բայց focus-ը չի տեղափոխում/սահմանափակում։ Իրական ReminderButton-ը բացելուց անմիջապես հետո focus-ը դրսում էր, Tab-ից հետո՝ ներսում, Shift+Tab-ից հետո՝ նորից դրսում։ `role=dialog` կա, բայց aria-modal և focus-ի վերադարձի կառավարում չկա։ Սա ընդհանուր բաղադրիչ է, ոչ միայն հիշեցման հատուկ պատուհան։

Ուղղում՝ սկզբնական focus, Tab/Shift+Tab շրջափակում, aria-modal, փակելուց հետո focus-ի վերադարձ։ Օգնության հատուկ պատուհանի նախկին ուղղումը ընդհանուր BottomSheet-ը չի փոխել։
