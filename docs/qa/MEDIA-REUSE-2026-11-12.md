# Մեդիայի արտաքին օգտագործում և պաշտպանություն — 2026-11-12

## Չափման արդյունքը

- Վերահսկվող փորձով օտար էջում մեր հանրային MP3-ը նվագարկվեց։ Սա տեխնիկական հնարավորության ապացույց է, ոչ իրական գողության կամ կոնկրետ կազմակերպության գործողության ապացույց։
- Հանրային տեքստը հասանելի է HTML-ում։ Ամբողջ կայքի օտար iframe-ը արդեն փակվում է CSP-ով, բրաուզերի արտաքին API ընթերցումը՝ CORS-ով։ Սերվերային հարցումները դրանցով չեն փակվում։
- [Միայն կարդացող Cloudflare չափում](https://github.com/T0n0yan/armenian-apostolic-digital-library/actions/runs/43241993362)՝ վերջին 24 ժամի համար։ Հաստատվեց Free Website փաթեթը։ `Zone Analytics Read` իրավունքը բացակայում է, իսկ վերնագրերի կանոնների ընթերցումը վերադարձնում է 403։ Իրական արտաքին հարցումների քանակն ու ծավալը **անհայտ են**, զրո չեն համարվում։
- Չափման գործիքը չի կարդում չատի տվյալներ, չի հավաքում IP-ներ, հաշիվներ կամ ամբողջական Referer հասցեներ։ Ստանում է միայն մեդիա դոմենների հարցումների համախմբում ըստ աղբյուրի դոմենի։ Cloudflare-ի տվյալները կարող են ընտրանքային լինել։ Արտաքին Referer-ը ինքնին չարաշահում չէ, բացակայողը՝ թույլատրելի կամ վնասակար լինելու ապացույց չէ։

## Կոդում ավելացվածը

`/media/`, `/place-media/`, `/help-media/` պատասխաններին ավելացվում է
`Cross-Origin-Resource-Policy: same-site`։ Սա արգելում է աջակցող բրաուզերում օտար կայքից
առանց CORS թույլտվության ուղիղ ներդրումը։ Նույն կայքը և նրա HTTPS ենթադոմենները շարունակում են աշխատել։
Կանոնը նույնն է ամբողջական և մասային պատասխանների, HEAD-ի ու քեշից ստացվող ֆայլերի համար։

Չեն փոխվում տեքստի ընտրությունը, պատճենումը, ներբեռնման հղումները, նվագարկիչը, չատը,
Google-ի համար էջերի հասանելիությունը կամ `/og/` նախադիտումների նկարները։ Սա բրաուզերի
պաշտպանություն է. սերվերով ներբեռնումը, էկրանի ձայնագրումը և արդեն պահված պատճենները չեն արգելվում։
CORP-ը հարցումների քանակի սահմանափակում չէ, ու փոխանցվող ծավալի կոնկրետ խնայողություն չենք խոստանում։
Նախկինում երկարաժամկետ քեշավորված պատասխանները կարող են հին վերնագրերով մնալ մինչև նոր բեռնումը։

## Cloudflare-ում մնացած մեկ կարգավորումը

Ուղղակի R2 դոմենը Worker-ի կոդով չի պաշտպանվում։ Ներկա API իրավունքը չի թույլատրում այնտեղ
կանոն կառավարել։ Հետևյալ կանոնը պատրաստ է ձեռքով ավելացնելու՝ առանց ֆայլերը Worker-ի միջով անցկացնելու։

1. Cloudflare → `apostolic.am` → Rules → Transform Rules / Response Header Transform Rules → նոր կանոն։
2. Անվանում՝ `Մեդիան միայն մեր կայքի էջերում`։ Պայման՝

   ```text
   http.host in {"media.apostolic.am" "media-staging.apostolic.am"}
   ```

3. Response header → **Set static** → `Cross-Origin-Resource-Policy` → `same-site`։
4. Պահել և միացնել։ Չավելացնել Referer-ի պարտադիր ստուգում կամ բոլոր բոտերի արգելք։ Եթե կանոնների ազատ տեղ չկա, նախ վերանայել առկա կանոնները, ոչ թե հեռացնել պատահական մեկը։
5. Ստուգել իրական մեդիա URL-ի HEAD և Range պատասխանները, ապա սաղմոսի նվագարկումն ու ձայնը առաջ տանելը՝ կայքում, PWA-ում և Telegram-ում։ Ստուգել նաև արտաքին փորձնական էջը. R2 ձայնը պետք է արգելափակվի, `/og/` նկարը՝ բացվի։

Խնդրի դեպքում անջատվում է հենց այս կանոնը։ R2 ֆայլերը, բազան և հղումները չեն փոխվում։
Google/Telegram սերվերային նախադիտումը CORP-ով չի արգելվում։ Այն արտաքին կայքերը, որոնք մեր
բնօրինակ մեդիան առանց միջնորդի դնում են իրենց էջում, կկորցնեն այդ հնարավորությունը։
Նախադիտումների համար նախատեսված `/og/` հասցեները բաց են մնում։

## Ինչ չենք խստացնում առանց ապացույցի

- Տեքստի ընտրության, աջ կոճակի կամ պատճենման արգելք չենք դնում. հեշտ է շրջանցել, վնասում է ընթերցողին ու մատչելիությանը։
- Բոլորին CAPTCHA, մուտք կամ ցածր IP սահմանաչափ չենք պարտադրում. ընդհանուր ինտերնետ օգտագործողներն ու մեդիայի մասային հարցումները կարող են տուժել։
- Ժամանակավոր ստորագրված մեդիա հղումներ չենք ավելացնում. կբարդացնեն քեշը, օֆլայնը և կարող են ավելացնել Worker հարցումները։
- Անհայտ բովանդակության վրա բացառիկ հեղինակային իրավունք չենք հայտարարում։ Օգտագործման պայմանները պետք է տարբերակեն սեփական ձևավորումը/ձայնագրությունները և երրորդ անձանց նյութերը։

Հետագա հասցեական սահմանափակման համար պետք է նախ Cloudflare-ի անանուն համախմբված
վիճակագրություն։ Հասանելիությունը տրամադրվում է Cloudflare/GitHub կարգավորումներում, գաղտնի
բանալիները չատում չեն փոխանցվում։ Առանց այդ չափման ամբողջ կայքի խստացումը հիմնավորված չէ։
