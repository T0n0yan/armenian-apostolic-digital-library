Մեծ պատկերը

Կայքի անունը Apostolic.am է (2026-11-17-ից, նախկինում՝ «Հոգևոր ժառանգություն»), կողքի տողը՝ «Հայաստանյայց Առաքելական Եկեղեցուն նվիրված»։ Անունը կոդում՝ SITE_NAME (app/utils/seo.ts). գլխավոր էջում տեսանելի վերնագիր և հավերժության նշան չկա, նկարի տակ միայն պիտակն է (app/components/home-title.tsx)։

Կայքը չունի սովորական սերվեր։ Ամեն ինչ աշխատում է Cloudflare-ում (Worker՝ կոդը, D1՝ բազան, R2՝ ֆայլերը)։ Նյութերի աղբյուրը Telegram խումբն է. GitHub-ը պարբերաբար դրանք պատճենում է կայք։

Սկզբունքը

  • Ընթերցողը երբեք ուղիղ Telegram-ից չի կարդում. ամեն ինչ արդեն կա D1-ում և R2-ում, դրա համար արագ է։

Հեռախոսի հավելվածներ (Android և iPhone)

Ինչպես է բացվում մեկ էջ

  • Կայքի լուսավորություն (թեմա), տառաչափ, շարժում (app/utils/preferences.ts, theme.ts). պահվում են բրաուզերում, էջը բացվում է արդեն ճիշտ գույնով (առանց «թարթման»)։
  • Մոմի ներածություն (candle-loader.tsx). օրը մեկ անգամ այս սարքում (localStorage library-loader-day, Երևանի օրով, նույն ստուգումը boot-script.ts-ում). Telegram-ը Mini App-ի ամեն բացումը նոր session է համարում, դրա համար session-ով չէ։ Մատով սեղմելիս բացվում է 0,4 վրկ-ում։ Մոմի տակ տառ առ տառ ոսկեգույն գրվում է «…Ես ձեզ հետ եմ բոլոր օրերին, / մինչև աշխարհի վախճանը» (Մատթ. 28:20՝ Էջմիածնի Աստվածաշնչից, VERSE_LINES), ստորակետից հետո դադար, վերջին տառից 0,5 վրկ հետո լույսը բացում է էջը (ընդհանուր ~6 վրկ)։
  • Edge cache-ը (workers/app.ts, handle()). բանալին՝ հասցե + contentVersion (նոր/փոփոխված գրառում կամ «Թարմացնել կայքը») + Երևանի օր (էջերը «այսօր»-ով)։ 5 րոպե թարմ է. գրադարանի էջերը (բաժին, նյութ, գլխավոր) 24 ժամ պահվում են և տրվում են անմիջապես, իսկ նոր պատճենը պատրաստվում է ֆոնում։ Սրբավայրերը, որոնումը և մյուսները՝ միայն 5 րոպե։ Cookie ունեցող (մուտք գործած) ընթերցողի առաջին բացման HTML-ը cache չունի (root-ում անձնականն է). Worker-ը աշխատում է բազային մոտ (placement: smart, wrangler.jsonc)։
  • Մուտք գործածների (Mini App) նավարկումը (app/utils/personal-data.ts). կայքի ներսում բեռնվող էջի տվյալները (<էջ>.data, route-եր՝ PUBLIC_DATA_ROUTES workers/app.ts-ում. գլխավոր, բաժին, նյութ, համար) loader-ները cookie չեն կարդում (isPageDataRequest), ուստի բոլորի համար նույնն են և տրվում են Cloudflare-ի և հեռախոսի cache-ից։ Անձնականը (պահածներ, կարդացել եմ, նշված համարներ, հարցման ձայն, ադմինի իրավունքներ) բերվում է զուգահեռ՝ /api/personal?kind=material|category&path=… (routes/personal-api.ts, private, no-store), և clientLoader-ը միացնում է։ Անանուն ընթերցողը այդ հարցումը չի անում։ tests/telegram-bridge.test.ts-ը ստուգում է, որ երկու ընթերցողի և անանունի .data-ն բայթ առ բայթ նույնն է։ Նոր route-ը PUBLIC_DATA_ROUTES-ում՝ միայն եթե նրա loader-ը .data-ի համար ընթերցողին չի կարդում։ Ամեն պատասխան ունի Server-Timing: edge;desc="hit|stale|miss|bypass", app;dur=…։

  • Նյութի էջը հիշողությունում (material.tsx clientLoader, "material-page"). ընդհանուր տվյալը 5 րոպե, նույն էջի revalidate-ը միշտ սերվերից։ Քարտերի և սաղմոսի ցանցի հղումները prefetch="intent" են, իսկ նյութի հղմանը մատը դիպչելիս (pointerdown, ոլորելիս՝ ոչ) սկսվում է անձնականի հարցումը (prefetchPersonal, root.tsx)։
  • Ոլորման դիրքը (<ScrollRestoration />, root.tsx) հիշվում է պատմության ամեն քայլի համար. մենյուից կամ հղումով բացված էջը միշտ վերևից է, «հետ»-ը վերադարձնում է նույն տեղը։ Առաջ դիրքը հիշվում էր հասցեով, ու մենյուից բացված բաժինը բացվում էր նախորդ անգամվա կեսից (2026-11-25)։

  • Մենյու (site-nav.tsx, .menu-panel). բացվում և փակվում է կոճակի կետից (scale(.2)), փակվելիս (data-closing, 320 մվ) մշուշը մնում է։ Բացվելիս (warmSections) բաժինների տվյալը (/<բաժին>.data?_routes=section, միասին ~40 ԿԲ) և գլխի նկարը (utils/category-image.ts) նախապես բերվում են. բրաուզերը դրանք պահում է 30 վրկ, ու սեղմելիս բաժինը բացվում է ~0,1 վրկ-ում (առաջ՝ 0,4–0,9)։ React Router-ի prefetch-ը clientLoader ունեցող էջերի տվյալը չի բերում, դրա համար՝ ձեռքով։ «Տվյալ խնայել» ռեժիմում՝ ոչ։ Route-ի id-ն (section) փոխելիս՝ փոխել նաև այստեղ։

Նյութերը. Telegram-ից կայք

Telegram-ի «սպասիր» (FLOOD_WAIT). մեծ ֆայլ ներբեռնելիս Telegram-ը կարող է ասել «սպասիր N վրկ»։ streamMedia-ն (gramjs-adapter.ts, floodWaitSeconds) սպասում է և շարունակում նույն բայթից (մինչև 20 անգամ, ≤120 վրկ)։ Եթե մեկ ֆայլ այնուամենայնիվ չհաջողվի, գրանցվում է library_sync_failures-ում, իսկ sync-ը շարունակում է մյուս գրառումները (wrangler-ի stdin-ի սխալը այլևս պրոցեսը չի գցում)։

Տեսանյութերի ավտոմատ սեղմում (scripts/optimize-videos.ts, կանոնները՝ shared/video-optimize.ts, աղյուսակ՝ video_optimizations)։ cloud-sync.yml-ի վերջին քայլն է, ուստի աշխատում է ամեն sync-ից հետո (նոր գրառումից 15 րոպե հետո և ամեն գիշեր)։ Գտնում է դեռ չսեղմված տեսանյութերը՝ Telegram-ից (library_media, kind='video'), կայքում ավելացված (material_attachments), սրբավայրերի (places.video_url) և օգնության (site_settings.help_videos)։ Ամեն մեկը սեղմվում է ffmpeg-ով MP4 / H.264 High 4.0 / AAC ձևաչափով (նվագարկվում է հին և նոր բոլոր հեռախոսներում և նոութբուքերում). Կանոններ v2 (2026-11-08, տիրոջ որոշում՝ առավելագույն սեղմում առանց որակը փչացնելու). CRF 30, կարճ կողմը ≤720, ≤30 կադր/վրկ, ձայնը՝ մոնո 40k (եթե ալիքները նույնն են) կամ ստերեո 64k, faststart։ Փորձարկված է կայքի տեսանյութերի վրա. v1-ի (CRF 26, 64k/96k) համեմատ −40%, SSIM 0.98, աչքով տարբերություն չկա։ HEVC/AV1 չենք օգտագործում. ոչ բոլոր հեռախոսներում և Telegram-ի ներսում են նվագարկվում։ Փոխարինվում է միայն եթե ≥15%-ով փոքր է (կամ եթե բնօրինակը ոչ բոլոր սարքերում է նվագարկվում՝ HEVC, WebM)։

  • Telegram-ի և կայքի ֆայլերը՝ նույն բանալիով (այդպես sync-ը դրանք նորից չի բերում). D1-ում թարմանում են

size_bytes, mime_type, r2_etag (?v=-ը փոխվում է, քեշը հինը չի տալիս)։ Sync-ը գրառումը վերագրելիս այս երեքը վերցնում է video_optimizations-ից։ Բնօրինակը փոխարինումից առաջ պահվում է originals/<բանալի>-ում։

  • Սրբավայրի և օգնության ֆայլերը՝ նոր բանալի …-o2.mp4 (v1-ը՝ …-o.mp4), հղումը փոխվում է միայն եթե ադմինը

միջանկյալ չի փոխել։

  • Բնօրինակը ջնջվում է նույն աշխատանքում (VIDEO_BACKUP_DAYS = 0), հենց որ սեղմվածը ստուգվեց. ճիշտ ձևաչափ,

  • Կանոնները փոխելիս (VIDEO_PROFILE, սյունակ video_optimizations.profile, migration 0052) արդեն սեղմվածները

նորից են սեղմվում բնօրինակից (երբեք՝ սեղմվածից), փոխարինվում են միայն եթե ≥3%-ով փոքր են, և միայն դրանից հետո է ջնջվում բնօրինակը։ Հին կանոններով «թողնված» (kept) ֆայլերը նորից են փորձվում։

  • Ձեռքով՝ Actions → Cloud sync → video_only (առանց Telegram-ի սինքի), video_limit (օր.՝ 1՝ փորձնական),

mode: dry-run (միայն ցանկը)։

  • Ձայնագրությունները (shared/audio-optimize.ts, AUDIO_PROFILE = "a1", նույն աղյուսակում՝ profile LIKE 'a%')

սեղմվում են նույն աշխատանքում, նույն կարգով (բնօրինակը՝ originals/-ում, ստուգում, ջնջում)։ MP3-ը մնում է MP3 (LAME VBR. ստերեո V4 ~110 kbps, խոսքը՝ մոնո V5), AAC-ը՝ AAC (96k/64k)։ Ներսի նկարն ու պիտակները հանվում են։ Տեսակը (mime_type) չի փոխվում (sync-ը ձայնագրության համար video/mp4 չի գրում)։ Ձայնային հաղորդագրությունները (Opus) և արդեն փոքր ֆայլերը (≤136 kbps ստերեո) չեն սեղմվում։ Սաղմոս 22. 2.5 ՄԲ → 0.8 ՄԲ։

Տեսանյութը փոքր պատուհանում (PiP) և էջից դուրս գալիս (app/utils/video-dock.ts, material-media.tsx)։

  • Առանձին PiP կոճակ չկա. PiP-ը նվագարկիչի ներսում է (բրաուզերի կոճակները՝ Chrome-ում ⋮ մենյուում,

Safari-ում՝ պատկերակով)։ Chrome-ը ինքն էլ է բացում PiP-ը ներդիրը/ծրագիրը փոխելիս (mediaSession → enterpictureinpicture, autopictureinpicture)։

  • Եթե տեսանյութը նվագում է, և մարդը գնում է կայքի մեկ այլ էջ, նույն <video>-ը (առանց կանգնելու,

moveBefore, որտեղ կա) տեղափոխվում է ձախ ներքևի անկյուն (.video-dock, × փակում է)։ Նույն նյութը նորից բացելիս անկյունինը փակվում է, իսկ էջի նվագարկիչը շարունակում է նույն տեղից. մեկ այլ տեսանյութի էջ բացելիս անկյունինը պարզապես փակվում է (takeDockedVideo)։ Այլ ձայն միացնելիս անկյունինը կանգնում է։ Եթե տեսանյութը բրաուզերի PiP-ում է, անկյան պատուհանը թաքնված է ([data-pip]), որ երկու պատուհան չլինի. PiP-ից դուրս գալիս, եթե դեռ նվագում է, նորից երևում է, կանգնածը՝ փակվում։

  • Անկյան պատուհանում բրաուզերի կոճակների փոխարեն մերն են՝ 10 վրկ հետ, նվագել/կանգնեցնել, 10 վրկ առաջ,

  • Բրաուզերից դուրս գալիս ձայնը չի կանգնում (app/utils/background-playback.ts, տեղադրվում է root.tsx-ում)։

Հեռախոսում (Android, iPhone) տեսանյութը միանալիս նախօրոք պատրաստվում է նույն հասցեով էջից անջատված <audio>։ Էջը թաքնվելիս ձայնը անմիջապես միանում է տեսանյութի տեղից, և միայն դրանից հետո տեսանյութը կանգնում է (մի պահ միասին, դադար չկա). վերադառնալիս՝ հակառակը։ iPhone-ում Safari-ն ֆոնում թույլ է տալիս միայն մարդու սեղմումով «բացված» էլեմենտ. ցանկացած touchend/click-ին play()+pause() (ձայն չի լսվում)։ Ձայնագրությունը (սաղմոս), եթե բրաուզերը թաքնվելուց 2 վրկ-ում կանգնեցրեց, նորից միանում է։ Համակարգչում ոչինչ չի փոխվում, եթե բրաուզերը ինքը չի կանգնեցնում։ Media Session՝ անուն, og:image, ▶/❚❚, 10 վրկ հետ/առաջ. ծանուցումից «կանգ»-ը հարգվում է։ Telegram Mini App-ում Telegram-ը ինքն է կանգնեցնում։

Սաղմոսներ (/psalms), Աղոթքներ (/pray), Սրբերի վարք (/saints), Ավետարանի ուսուցում (/gospel), Օրվա ընթերցումներ (/daily), Հարցեր Աստվածաշնչից (/questions), գրառումներ (/post)։ Հին հասցեները (/pray_364) 301-ով տանում են նորերին։ Ավետարանի ուսուցումը բեռնվում է ամբողջությամբ (մինչև 200, ինչպես աղոթքները) և բաժանվում է թաբերի՝ ըստ հոգևորականի. անունը տեսանյութի տակի վերջին շեղ տողն է (clergyByline(), material-title.ts → MaterialCardPreview.clergy)։ Որոնման արդյունքում (կայքի և բաժնի որոնում) քարտի վերնագրի տակ շեղ գրվում է հոգևորականի անունը։ Թաբերը երևում են միայն երբ ≥2 հոգևորական կա. անուն չունեցողները՝ «Այլ տեսանյութեր»։ Նոր հոգևորական ավելացնելու համար կոդ պետք չէ՝ բավական է Telegram-ում նրա անունը գրել վերջին տողում շեղ։

Ժամերը տեքստում (telegram-content.tsx, TimestampText). «01:09»-ի նման ժամը տեսանյութ/ձայն ունեցող էջում սեղմելի է և տանում է այդ պահին։ Աստվածաշնչի հղումները ժամ չեն համարվում (utils/verse-reference.ts). կետով կրճատ գրքի անունից հետո («Մատթ. 7:13»), միջակայքով («7:13-14») կամ նույն ցանկում ստորակետից հետո («5:3, 6:9»)։ Ստուգվում է ամբողջ պարբերության տեքստով, որ ընդգծված կամ հղում դարձած «7:13»-ն էլ ճանաչվի։

Նյութի էջը (material.tsx). տեքստ (rich-text, telegram-content), մեդիա (material-media), սաղմոսի տող առ տող ընթերցում ձայնի հետ (psalm-read-along, psalm_timings), նախորդ/հաջորդ սաղմոս, կիսվել, պահել, «Կարդացել եմ», հիշեցում, բառարանի բառեր, հարցման քվեարկություն։ Կայքում ավելացված ձայնագրություններ (material_attachments), երբ Telegram-ը չի կարող (երկար տեքստ)։ Սաղմոսից սաղմոս անցնելիս (isPsalmPagePath) էջի կմախքը (navigation-progress.tsx → PageSkeleton) չի ցուցադրվում. էջը մնում է տեղում, article-ը բեռնման ընթացքում թեթև մարում է, հետո փոխվում է միայն բովանդակությունը։

Էջերի կմախքները (page-skeleton.tsx, բեռնվում է առանձին ֆայլով navigation-progress.tsx-ից). եթե էջը 160 մվ-ից երկար է բացվում, ցույց է տրվում նրա կմախքը (0,09 վրկ-ում, որ հին և նոր էջերը իրար վրա չերևան)՝ իրական էջի նույն կառուցվածքով. բաժնի գլուխը (նկար, անուն, որոնման կլոր կոճակ), կայքի համար գրված ներածությունները (SECTION_INTROS, category-cards.tsx), գլխավոր էջի վերնագիրը (home-title.tsx) և օրվա համարը նկարվում են նույն բաղադրիչներով, ինչ էջում, իսկ բաժնի անունը, սաղմոսի ու համարի թիվը գրվում են իսկական տեքստով։ Ամեն բաժին (սաղմոսներ, աղոթքներ, սրբեր, ավետարան, օրվա ընթերցումներ, հարցեր), նյութի էջ, որոնում, «Իմ անկյունը» (մուտք գործածի/չգործածի համար տարբեր), սրբավայրեր, օգնություն ունի իր կմախքը։ Էջի տեսքը փոխելիս՝ թարմացնել նաև կմախքը։ Կմախքի վերնագիրը ենթարկվում է «Վերնագրի չափ» կարգավորմանը (.page-skeleton h1, .page-skeleton-title, app.css), այլապես վերնագիրը նախ մեծ էր, հետո փոքրանում էր։ «Հետ» գնալիս (popstate) կմախք չկա. էջը վերադառնում է իր դիրքին, իսկ կմախքը միշտ վերևն է։

Աղոթքների ձևավորում (prayer-layout-editor.tsx, prayer-layout-view.tsx, utils/prayer-layout.ts). աղոթքի էջում «Ձևավորել» կոճակը (միայն գլխավոր ադմին կամ layout իրավունքով) բացում է խմբագիր. ամեն պարբերության տեսակ (տեքստ / նկարագրություն / պիտակ), դիրք, չափ, տառատեսակ (գրքային / սերիֆ / սովորական), թռչնատառ, ամբողջը թավ/շեղ, «Աղոթք» նշան (բուն աղոթքի պարբերությունները՝ ընթերցողին չի երևում, հետագա «կիսվել աղոթքը նկարով»-ի համար, prayerParagraphs()). ընտրված բառերին/տառերին՝ թավ, շեղ, ոսկեգույն, կարմիր, չափ, տառատեսակ. տեքստի ուղղում, պարբերությունների բաժանում/միացում/տեղափոխում, հետարկում։ Պահվում է material_layouts-ում (migration 0050, /api/material-layout)՝ Telegram-ի տեքստից առանձին, սինքը չի ջնջում։ Ձևավորում ունեցող աղոթքը էջում ցույց է տրվում այդ ձևով (.reading-body-ի մեջ, այնպես որ նշումները և բառարանը աշխատում են), մեդիան՝ վերևում։ source_hash-ը Telegram-ի տեքստի նշանն է (sourceHash). եթե Telegram-ում տեքստը փոխվի, ադմինը էջում և խմբագրում զգուշացում է տեսնում և կարող է սկսել նոր տեքստից։ Պահելը/ջնջելը բարձրացնում է քեշի epoch-ը, որ էջը բոլորի մոտ թարմանա։ Ձայնագրություն ունեցող ձևավորված աղոթքում տող առ տող ընդգծումը չկա։ Ձևավորման տարբերակը՝ v: 2 (v1-ի նկարագրությունները բեռնելիս դառնում են շեղ, «Աղոթք»-ը՝ ըստ տեսակի)։

Sitemap-ը բաց է թողնում բաժնի ներածական գրառումները՝ նույն կանոնով, ինչ որոնման ինդեքսը (INTRO_TOPICS, առաջին տեքստային նյութ՝ առանց պատրաստ մեդիայի)։ Դրանց հին էջերը պահպանվում են։ Սաղմոսի համարի էջը (/psalms/47/3) պահպանում է իր UI-ը, կիսվելու og:url-ն ու նկարը, իսկ canonicalPath-ը ցույց է տալիս ամբողջ սաղմոսը (/psalms/47)։ Canonical հասցեները production դոմենով են, staging-ը շարունակում է ունենալ X-Robots-Tag: noindex։ Սաղմոսի որոնման վերնագրում միշտ նշվում է համարը (materialSeoTitle)։ Հանրային sitemap-ի ամբողջական ստուգում՝ node scripts/seo-audit.mjs https://apostolic.am․ երկու զուգահեռ հարցում, HTTP/canonical/noindex/title/description/H1 ստուգումներ։ Սա Google-ի ինդեքսավորման երաշխիք կամ Search Console-ի տվյալների փոխարինում չէ։

  • Մտնում են միայն երկու կողմ. «a»՝ միայն CHAT_OWNER_ACCOUNTS-ի (production, wrangler.jsonc. չկա՝ OWNER_ACCOUNTS) հաշիվները կամ դրանց կապված հաշիվները (isOwnerIdentity), ոչ թե «գլխավոր ադմին» դարձված մյուսները. «b»՝ ստացողը (նույնպես կապված հաշիվներով)։ Մնացած բոլորին էջը, socket-ը և ֆայլերը 404 են։
  • Ամեն ինչ (տեքստ, նկար, ձայն) պահվում է միայն ChatRoom DO-ի SQLite-ում (workers/chat-room.ts, ֆայլերը՝ 1 ՄԲ կտորներով), ոչ թե D1-ում կամ R2-ում (R2-ն ունի հանրային media հասցե). ուստի չկան backup-ում, ադմինի էջերում։ Ֆայլերը՝ private, no-store, sandbox CSP, միայն JPEG/PNG/WebP/GIF և webm/ogg/mp4/mpeg/aac (SVG՝ ոչ)։ Ջնջելիս տեքստը/ֆայլը իսկապես ջնջվում է. «Ջնջել ամբողջ զրույցը»՝ միայն տերը (մնում են կարգավորումները)։

  • Տիրոջ ⚙-ում «Ստուգում» (chatDiagnostics). ստացողի հաշիվները (Google/Telegram), մտե՞լ է արդյոք և երբ, ծանուցումների ուղիները երկու կողմի համար (Telegram բոտ, բրաուզերի push)։ Նամակների տեքստ չկա։ Ամեն socket-ին կցված է where և visible (statusOf)։
  • Ամեն կողմի կարգավորումը (DO state). ինչ անունով է տեսնում մյուսին (nick_<side>), տեքստի չափը (font_<side>), ֆոնը (bg_<side>՝ իր նկարը DO-ում, չկա՝ ընդհանուրը) և ֆոնի թափանցիկությունը (bgop_<side>)։ Ընդհանուր ֆոնը կոդում է (app/data/private-chat-background.server.ts, ռեպոն փակ է), տրվում է GET /namak/background-ով միայն կողմերին, ոչ թե public/-ից։ Ֆայլերը՝ Cross-Origin-Resource-Policy: same-origin։ Նամակը՝ մինչև 50 000 նշան, փոփոխելի (միայն տեքստը, «փոփոխված»)։ Պատասխան (reply)՝ ցանկացած նամակին (իր կամ մյուսի). messages.reply_to, կարդալիս LEFT JOIN-ով բերվում է մեջբերման կարճ տեքստը (200 նշան), մեջբերման վրա սեղմելիս՝ գնում է բուն նամակին։
  • Ստացողը նշվում է տիրոջ «Կարգավորում»-ում (Gmail կամ @username → անփոփոխ id-ներ)։ Չջնջված նամակներ ունենալուց հետո ստացողին փոխել չի կարելի։ Ամեն պահելիս resetRecipient-ը փակում է նախկին ստացողի բաց socket-ները և ջնջում նրա members-ը, «վերջին անգամ»-ը և կարգավորումները (նույն ստացողինը՝ ոչ), որ նրան ոչ նամակ, ոչ ծանուցում չհասնի։

Որոնում

Էջի ներսում որոնում (page-find.tsx). բաժնի ցուցակը նեղանում է մուտքագրելիս։

«Գուցե նկատի ունեիք» (shared/search-correction.ts). լատինատառը դառնում է հայերեն, տառասխալը ուղղվում է ըստ վերնագրերի բառերի (սերվերում՝ app/data/search-correction.server.ts, 10 րոպե հիշողության մեջ, հեռախոսում՝ վերնագրերի ինդեքսից)։ Լատինատառ կամ ոչինչ չգտած որոնումը բացվում է ուղղվածով (/search?q=սաղմոս&asked=Saxmos). ոչինչ չգտած որոնումը, որի ուղղումը վստահ չէ, բացվում է ամենամոտ բառով։ Ուղղված բառը դրվում է հենց որոնման դաշտում, առանձին հուշում չկա (&exact=1՝ որոնել ճիշտ գրածը)։ Հեռախոսի ինդեքսում սաղմոսի համարը վերցվում է նաև ձայնագրության անունից (search-index.server.ts), R2-ի պատճենը ունի ձևի համար (<version>:2)։ Մնացածում՝ «Գուցե նկատի ունեիք» և «Նման բառեր» կոճակներ։

Այլ լեզուներ (shared/search-foreign.ts). անգլերեն, ռուսերեն, ֆրանսերեն, իսպաներեն, գերմաներեն, իտալերեն, արաբերեն, պարսկերեն բառերը («psalm», «молитва», «prière») դառնում են հայերեն բառը և բացվում են դրանով (?q=Սաղմոս&asked=psalm), սերվերում էլ, հեռախոսում էլ։ Ռուսատառ հայերենը («сагмос») դառնում է լատինատառ, հետո՝ «Գուցե նկատի ունեիք»-ով հայերեն։ Նոր բառ՝ FOREIGN_TERMS-ում։ Հեռախոսում բաժնի անունով որոնումը («Սաղ», «saxmos») բերում է այդ բաժնի նյութերը՝ վերնագրով գտածներից հետո։ «Ճշգրիտ համընկնում չգտնվեց»-ը երևում է միայն երբ բոլոր արդյունքները տառասխալով են։

Բառի տեղը տեքստում (foldedMatches, shared/telegram-search.ts). հին և նոր ուղղագրությունը համեմատվում են (անիրավ = անիրաւ, Տեր = Տէր, թյուն = թիւն)։ Օգտագործվում է արդյունքի հատվածում (locateStoredSearchHit) և բացված էջում բառի ընդգծման համար (app/utils/find-flash.ts)։

Որոնման դաշտը՝ անկյունի կոճակից (ExpandingSearch, app/components/page-layout.tsx). ամեն էջի (բացի գլխավորից) որոնումը բացվում է վերնագրի տողի կլոր կոճակից, էջն իջնելիս կպչում է էկրանի վերևին, Enter-ից հետո ստեղնաշարը փակվում է։ Բաժնում գտնվածները պայծառ են, մնացածը՝ մեղմ ([data-finding])։

export function easterDay(year: number) {
  const a = year % 19, b = Math.floor(year / 100), c = year % 100, d = Math.floor(b / 4), e = b % 4;
  const f = Math.floor((b + 8) / 25), g = Math.floor((b - f + 1) / 3), h = (19 * a + b - d - g + 15) % 30;
  const i = Math.floor(c / 4), k = c % 4, l = (32 + 2 * e + 2 * i - h - k) % 7, m = Math.floor((a + 11 * h + 22 * l) / 451);
  const month = Math.floor((h + l - 7 * m + 114) / 31);
  const day = ((h + l - 7 * m + 114) % 31) + 1;
  return `${year}-${month}-${day}`; // իրականում՝ երկնիշ ամիս/օր
}
